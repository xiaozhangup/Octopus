# Hamster

Hamster 是 Octopus 的本地异常记录机制。服务端将异常保存为 JSONL；本目录的静态前端读取手动下载的文件。没有 Sentry SDK、网络上报、服务端查询命令或前端构建依赖。

## 使用

1. 使用包含 Hamster 的 Octopus 构建启动服务器。
2. 从服务器的 `logs/hamster/` 下载所需的 `.jsonl` 文件。记录最多约一秒刷新一次；下载正在写入的文件可能得到不完整末行。
3. 打开 `hamster/index.html`，通过文件选择器或拖放导入。可同时导入多个文件，后续导入继续追加；重复异常记录按会话和记录 ID 去重。
4. 在顶部按插件、级别、来源、启动会话和时间范围筛选；搜索覆盖消息、异常类、线程、上下文、记录 ID、指纹和对应样本的堆栈。各条件同时满足才保留记录，堆栈命中会保留引用该样本的发生记录。
5. 左上表格按指纹分组，左下表格展示所选分组中匹配筛选的发生记录；右侧显示所选记录的消息、堆栈与上下文。前置日志按需展开。完整样本与重复发生的引用样本会明确区分。

分组表格的「匹配 / 总计」分别表示当前筛选命中的次数和已导入的分组总次数；排序与最近发生时间也使用匹配记录。顶部统计始终表示全部已导入文件。时间按页面标注的浏览器本地时区显示，包含毫秒；时间范围包含两端，结束时间包括所填秒内的全部毫秒。支持按最近发生、匹配次数、首次发生排序。列表每页最多 50 行，分组、发生记录和详情分别滚动。

快捷操作：点击整行选择；在分组或发生列表中用 ↑ / ↓ 切换并自动翻页；按 `/` 聚焦搜索，搜索框内按 Esc 清空搜索。堆栈可切换自动换行，导出报告包含所选发生记录和其引用样本的信息。

如果浏览器限制本地文件页面，可在项目根目录运行 `python3 -m http.server 8765 --bind 127.0.0.1 --directory hamster`，然后打开 `http://127.0.0.1:8765/`。该服务只提供静态资源；文件仍由浏览器本地读取。

前端不发送请求、不持久保存日志，刷新或清空工作区后移除当前导入的数据。支持导出所选异常的纯文本报告。文件作为不可信输入处理：文本只通过 DOM 文本节点显示，格式错误的行会跳过并提示；不支持的 schema 版本不会被猜测解析。单个导入文件限制为 64 MiB。

## 服务端配置

`config/paper-global.yml` 中新增以下配置，重启后生效：

```yaml
hamster:
  enabled: true
  directory: logs/hamster
  retention-days: 7
  max-disk-mib: 256
```

保留天数必须大于零，容量至少为 16 MiB。配置不合法或目录无法写入时，通过 Log4j 内部状态日志报告并停用 Hamster。使用每个服务器独立的目录。

- 捕获根日志器接收到的 WARN / ERROR / FATAL 且携带 `Throwable` 的日志。纯文本错误作为前置日志；被吞掉或未记录的异常无法捕获。
- 保留最近最多 100 条全服日志，异常样本中的日志文本和元数据有总长度限制；原时间与线程均保留。前置日志提供时间窗口，不代表因果关系。
- 在事件、插件启停及生命周期、同步与异步调度任务的异常日志处补充上下文。事件仅提取明确的类型与字段，没有反射遍历。普通插件自行记录的错误保留 Logger 名，插件与玩家字段可能缺失。
- 世界 tick 内的日志带世界和维度；跨线程返回的世界崩溃保留原世界线程，通过原有 `ReportedException` 崩溃路径记录一次。
- 日志调用线程复制异常消息、cause、suppressed、堆栈及上下文。队列没有 Bukkit 对象、插件实例、原始异常或 LogEvent；后台线程仅分组和写文件。
- 队列上限 1,024 条。满时丢弃新快照并记录 `loss` 数量，普通服务端日志继续工作。过长消息和堆栈会截断，堆栈保留截断标记。
- 单文件约 16 MiB 轮转，跨天也轮转。每个文件独立包含会话头和其中引用的异常定义。分组缓存最多 1,024 组，淘汰后再次出现时重新保存完整样本。
- 每分钟、轮转和关闭时清理过期文件与超额文件，仅处理符合 Hamster 命名规则的普通文件。当前文件不删除，容量目标可能暂时超出一个文件的大小。
- 插件启用前开始记录，正常停机在退出前最多等待两秒排空队列。文件错误时停止记录；强制结束或排空超时可能丢失未写入的数据。

## JSONL v1

每行是独立的 UTF-8 JSON 对象，公共字段为 `schema: 1`、`type` 和 `session_id`。

| type | 内容 | 前端计数 |
| --- | --- | --- |
| `session` | `started_at`、`server`、`java`、`part`；每个文件重复提供本次启动信息 | 一个启动会话 |
| `issue` | 一次发生记录及完整 `stack`、`truncated`、`breadcrumbs` | 一次异常，提供完整样本 |
| `occurrence` | 同类异常再次发生的消息和上下文，引用 `issue_id` | 一次异常 |
| `loss` | 唯一 `id`、`time`、`count`、`reason: queue_full` | 丢弃数，不计为已保存的异常 |

`issue` 和 `occurrence` 均包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 会话 UUID 加发生序号；序号只要求唯一，写入顺序不能作为跨线程因果关系 |
| `issue_id` / `fingerprint` | 64 位十六进制 SHA-256 指纹 |
| `time` | 日志产生时间，Unix 毫秒；前端按浏览器本地时区显示 |
| `level`、`logger`、`thread` | 原日志的级别、Logger 名和线程名 |
| `message`、`exception` | 格式化日志消息和最外层异常类名 |
| `context` | 字符串映射；例如 `source`、`plugin.name`、`plugin.version`、`task.id`、`event`、`listener`、`player.uuid`、`world`、`dimension`、`world.thread` |

完整样本的 `breadcrumbs` 是包含 `time`、`thread`、`level`、`logger` 和 `message` 的数组。指纹使用服务端构建、插件名称与版本、来源、事件类型以及异常类型链和堆栈类名/方法名；不使用行号、玩家、坐标或动态消息。分组表示相同异常路径，不保证相同根因。截断的大堆栈按保留的部分分组。

发生记录的计数来自已导入文件。只下载部分文件时，页面无法得知未导入部分的总次数。缺少完整样本或会话头会明确提示；损坏行、末行截断和不支持的格式也会显示导入提示。
